## Efficient operation

- Scope investigations to the files and question at hand.
- Prefer targeted searches and small reads; avoid generated directories, lockfiles, and large logs unless needed.
- Use compact command output (RTK) and run focused checks rather than broad scans.
- Do not repeat context or tool output already available in the session.
- For multi-file or risky changes, inspect first and state the intended changes before editing.
- Prefer the smallest sufficient change; avoid unrelated refactors.
- Run the narrowest relevant validation before a full build or test suite.
- For ambiguous requirements, ask one focused question before broad investigation.
- Stop once the requested result is verified; report remaining uncertainty instead of exploring further.
- Use a new session for unrelated tasks rather than carrying old context forward.
